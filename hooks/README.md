# fast-jev-compaction Claude Code mod

This plugin uses Claude Code function hooks to replace a compaction with the
original messages, minus the tool calls and tool results Jev judged no longer
needed. `hooks/fast-jev.ts` is a thin adapter: it reads the plugin options,
finds the API key, hands `session.compact` transcripts to the
`fast-jev-compaction` library in `src/` (the plugin folder is the repository
root, so the hook imports it directly) and maps the result back onto session
messages. User and assistant text is never touched. Jev is sent the whole
conversation as `state` (tool outputs replaced by a one-line note) and, for
every tool call outside the pinned first and newest messages, two questions:
whether the call should stay and whether its full output should stay. An
item is kept when Jev's probability reaches `keepThreshold`; a dropped result
is truncated to its first `truncateHeadChars` characters plus a one-line note,
and a dropped call disappears with its result.

The state is fitted into `maxStateTokens` in stages: tool inputs are
truncated, then long texts are abridged (oldest first, pinned messages last),
then old messages collapse to a `[… N chars omitted …]` note, then old tool
calls shrink to one line each, then old call-less messages are left out and
runs of old call-only messages fold together. Questions are split into as many requests as
needed so each request (state plus questions) stays under `maxRequestTokens`;
the full state is resent with every request. Token counts are estimated
without a tokenizer, calibrated to land a little above what Jev reports.

### The two Jev APIs

The plugin speaks both of Jev's APIs and picks one per compaction:

| | `systemone` | `gateway` |
| --- | --- | --- |
| Endpoint | `POST https://api.typesafe.ai/v1/systemone` | `POST https://ai-gateway.vercel.sh/v4/ai/evaluation-model` |
| Key | `TYPESAFE_API_KEY` | `AI_GATEWAY_API_KEY` |
| Default model | `jev-latest` | `typesafe-ai/jev` |
| Model travels in | the request body | the `ai-model-id` header |
| Boolean primitive | `noul` question, `noul` answer | `boolean` question, `probability` answer |
| Adapter | `jevAsker` in `fast-jev.ts`, over `src/request.ts` | `hooks/gateway-asker.ts` |

`provider` picks between them; `auto` (the default) decides like this:

1. a `provider` option always wins;
2. otherwise the key's name decides — a key read from `AI_GATEWAY_API_KEY` is a
   Gateway key, one read from `TYPESAFE_API_KEY` is a System One key, so an
   install from before the Gateway move keeps working unchanged and one set up
   for the Gateway needs no configuration either;
3. only for a key with no such name (the `apiKey` plugin option) does the model
   id break the tie: Gateway ids are namespaced (`typesafe-ai/jev`), System One
   names are bare (`jev-latest`);
4. with nothing to go on, the Gateway.

Set `provider` explicitly when a machine holds both keys and the default order
(Gateway first) is not what this install should use. The chosen provider also
decides which key name is read first, so a `provider: systemone` install picks
up its own credential on a machine that also has a Gateway key. `baseUrl`
overrides the endpoint of either.

The Gateway is spoken directly over `$.http.fetch` in `hooks/gateway-asker.ts`:
a hooks module may only import its own files and `claude-code`, so the `ai` and
`@ai-sdk/gateway` packages cannot be used here, and going over `$.http.fetch`
also keeps the request inside the engine's own transport. The Gateway calls the
primitive `boolean` where System One calls it `noul`, and returns `probability`
where System One returns `noul`, so the adapter renames that one case in each
direction and leaves `choice` and `score` untouched. The library in `src/`
speaks only to System One; the Gateway translation lives in the plugin.

The mod is an early-access Claude Code function-hook module. The checked-in
type reference was generated by Claude Code **2.1.274**. Enable the function
hooks surface before installing or loading it:

```sh
export CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1
# Either key works; see "The two Jev APIs" above.
export AI_GATEWAY_API_KEY="<your Vercel AI Gateway key>"
# export TYPESAFE_API_KEY="<your TypeSafe key>"

claude plugin marketplace add tamaratran/fast-jev-compaction
claude plugin install fast-jev-compaction@fast-jev-compaction
```

For local development:

```sh
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir .
```

## Configuration

The plugin declares these `userConfig` values in
`.claude-plugin/plugin.json`:

| Option | Default |
| --- | ---: |
| `keepThreshold` | `0.5` |
| `preserveRecentMessages` | `6` |
| `compactAtPercent` | `60` |
| `minReductionRatio` | `0.25` |
| `maxStateTokens` | `25000` |
| `maxRequestTokens` | `30000` |
| `truncateHeadChars` | `300` |
| `provider` | `auto` |
| `model` | the provider's default |
| `baseUrl` | the provider's default |

`provider` is `auto`, `gateway` (or `vercel`) or `systemone` (or `typesafe`);
anything else is read as `auto`. `model` is the Jev model id in the chosen
API's own spelling, and both it and `baseUrl` default to the provider's.

The key can be supplied as the sensitive `apiKey` plugin option or through
`AI_GATEWAY_API_KEY` or `TYPESAFE_API_KEY`; both names are also read from
settings' `env`, and the key given as a plugin option carries no provider hint.
The environment variable is the recommended development setup.

Every option except `apiKey`, `compactAtPercent`, `minReductionRatio`,
`provider`, `model` and `baseUrl` is passed straight to the library; see the root README for what they
do. The `session.compact` hook runs the Jev requests concurrently. If Jev fails,
the response is malformed, the key is unavailable, the history cannot be
fitted into the state budget, or the estimated reduction is below
`minReductionRatio`, the hook logs a fallback and delegates to Claude Code's
built-in compaction. The outcome is shown as a toast and logged with the
reduction, per-reason counts, state size and request count; a per-call
`decisions:` line with both probabilities is logged for diagnosis. The
`turn.complete` hook requests
compaction when `context.percent` reaches `compactAtPercent`, with an
in-flight guard.

## Scope and caveat

Function hooks are early access and may change between Claude Code releases.
This mod uses the generated declarations from 2.1.274 in
`types/claude-code.d.ts`; regenerate and review that file after a
Claude Code upgrade.
