# Compaction hardening

These changes tighten the existing compactor. They do not make pruning lossless, change the classifier, or certify a Claude Code release.

## Configuration

The library accepts `maxConcurrentRequests` in `CompactOptions`. It defaults to 4 and is resolved to a finite integer of at least 1. This limits simultaneous batches within one compaction, not requests per minute or concurrent sessions. After a failed batch, the scheduler stops taking queued work and waits for already-started work to settle. No partial transcript is returned. The Claude Code adapter uses the default; this patch does not add a plugin configuration control for it.

`JevClient` and `compactMessages` accept `timeoutMs` and `signal`. The default deadline is 15,000 milliseconds per request, including response-body consumption. `timeoutMs` must be an integer from 1 through 2,147,483,647. A supplied `AbortSignal` cancels requests from that client. Custom fetch implementations receive a signal, but the client cannot stop arbitrary custom code that ignores it. These options are not supported by the host's `$.http.fetch` adapter and are not an overall compaction deadline.

`keepThreshold` must be within `[0, 1]`. The existing fallback for non-finite values passed to `resolveOptions` is retained. Direct `decideCall` callers must provide a valid threshold and two valid probabilities. Raising the keep threshold makes deletion more aggressive, not safer.

## Failure behavior

Response parsing rejects array-shaped answer maps, malformed answer objects, conflicting discriminators, inherited answer properties, and probabilities outside `[0, 1]`. An absent discriminator remains accepted for existing injected adapters.

Duplicate tool-call IDs, duplicate results, and results before their calls are rejected. The library still accepts partial histories with an unmatched call or orphan result; neither becomes a deletion candidate. `applyDecisions` cannot override a pinned call. Callers should not fabricate `ToolCall` records that bypass collection.

Pending tool calls are included in `state.history[].pending_calls`. They remain outside the scoring candidates and cannot disappear during deep state fitting. This can make a pending-heavy history fail its budget instead of silently omitting the pending work.

The effective state budget now reserves room for the largest candidate's question pair and the request envelope. This is still a heuristic token estimate. It is not the provider's tokenizer or a guarantee that an upstream request will fit.

## Claude Code adapter

The automatic-compaction lock is acquired before the first asynchronous usage read. Logging and toasts are best-effort and cannot replace a valid result or prevent the handler's native fallback. Explicit `/compact` instructions are appended to the configured or inferred goal supplied to Jev. This conveys the instructions to the classifier; it is not a deterministic guarantee that the classifier will follow them.

The vendored declarations were generated by Claude Code 2.1.274. Runtime compatibility must be checked against the actual installed function-hook build. Public command-hook events and early-access function-hook events are different interfaces.

## Tests and packaging

Run the existing checks and the new offline contract tests from a complete checkout:

```sh
npm ci
npm run typecheck
npm test
npm run test:regressions
npm run build
npm pack
```

The regression runner uses the existing TypeScript development dependency to transpile a temporary copy and runs Node's test runner. Transpilation is not a substitute for `typecheck`. The `*.case.mjs` names keep these tests out of Vitest's default `*.test.*` discovery.

To compare the same regression cases with an earlier checkout:

```sh
node scripts/test-regressions.mjs --source /absolute/path/to/baseline
```

A baseline checkout needs its development dependencies for the packaging case. `prepack` builds the exported JavaScript and declarations before creating an npm archive. Consumers must receive a built artifact; installation with scripts disabled must not be expected to compile the source.

## What remains unproven

Offline tests cover control flow and structural invariants. They do not measure Jev's recall, safe deletion, actual model-context tokens, prompt-cache impact, or a native Claude Code compaction. Before a release, run a real host test with a mixed-content transcript and the lockfile's toolchain. Keep a reversible transcript checkpoint and evaluate critical-fact retention separately from character reduction.
